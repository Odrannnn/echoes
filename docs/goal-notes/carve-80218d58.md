## The body, and why it is that body

```c
struct STryclopsLoaderSlot { void* loader; /* FScriptLoader */ };
extern struct STryclopsLoaderSlot* gLoader_Tryclops;
void fn_80218D58(struct STryclopsLoaderSlot* record) { gLoader_Tryclops = record; }
```

**The argument is the *address* of a slot, not a loader**, and that is measured off the two
callers in module 81's own listing
(`build/G2ME01/Tryclops/asm/MetroidPrime/ScriptObjects/CTryclopsRel.s`):

* `RELExit` at `.text:0x104`, 0x24 bytes: `li r3, 0x0` ... `bl fn_80218D58` - teardown.
* `fn_81_148` at `.text:0x148`, 0x30 bytes: `lis r3, lbl_81_bss_30@ha`, materialises
  `fn_81_178` with `lis r4` + `addi r0`, `stwu r0, lbl_81_bss_30@l(r3)`, then
  `bl fn_80218D58` with **r3 still pointing at `lbl_81_bss_30`**.

`config/G2ME01/rels/Tryclops/symbols.txt:225` gives `lbl_81_bss_30 = .bss:0x30 size:0x4
data:4byte`, so the record handed over is **0x4 bytes - a bare `FScriptLoader`, no member
pointer**. That is the narrowest form of this family: SpacePirate's is 0x1C and MetroidAlpha's
0x10, both because their module passes a CodeWarrior pointer-to-member-function after the loader.
The DOL confirms it twice over: `LoadTryclops` at 0x80218D2C does
`lwz r6, gLoader_Tryclops@sda21(r0); lwz r12, 0x0(r6); mtctr r12; bctrl`
(`build/G2ME01/asm/MetroidPrime/ScriptLoader/Tryclops.s`), and **nothing in the DOL reads `+4`
off this slot**, where MetroidAlpha's `OnDockTouch__13CMetroidAlpha` does
`addi r12, r5, 0x4; bl __ptmf_scall` on it. Only the address is ever stored, so the struct's
field types describe the shape rather than a layout this unit reads.

The struct tag is declared **above** the prototype, not inside the parameter list: a tag first
seen in a prototype is scoped to that list and the host build then rejects the definition as a
conflicting type. Same reason `Carve80200E3C.c:56` and `Carve80218B68.c:73` put theirs above.

**The name cannot move, and the carve is what removes the exception without renaming anything.**
`Tryclops.cpp:6-8` recorded that the setter was deliberately left unclaimed - "REL modules import
it by its retail name, so it cannot be renamed and must stay in dtk's auto unit". The import name
is the plain `fn_80218D58`: line 281 of `strings build/G2ME01/Tryclops/Tryclops.preplf`. So a C
definition of that exact symbol keeps it in the DOL link and module 81's two `bl fn_80218D58`
resolve against it. `.c` rather than `.cpp` because `build.ninja` appends `-lang=c` to the `.c`
rule: without it mwcceppc mangles to `_Z<len>fn_80218D58v` and objdiff pairs nothing
(`Carve800069AC.c:36-40`).

**`PortLinkStubs.cpp` had no duplicate** - `grep -rn 80218D58` over `src/` found only
`CTryclopsRel.cpp` (which *declares* the plain C symbol at line 124 and calls it from `fn_81_148`
and `RELExit`, both unchanged) and `Tryclops.cpp`'s comment. So nothing had to be deleted, and
`gate.sh`'s `port link dups` step passed.
