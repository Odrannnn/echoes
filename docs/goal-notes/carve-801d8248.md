## Notes for the next lane (not filed as `NEW:`, they are not work)

- **`tools/carve_diff.sh` reports `NOT byte-exact` on a carve that is byte-exact.** Its
  `INSN` regex is `^\s*([0-9a-f]+):\s+((?:[0-9a-f]{2} ){3}[0-9a-f]{2})\s+(\S+)\s*(.*)$`, which
  assumes `objdump` prints `   0:  38 00 00 00  li ...`; the `build/binutils/powerpc-eabi-objdump`
  in this tree prints a wider address column (`   0:\t38 00 00 00 \tli ...`), so the regex never
  matches and `ours` comes back as 0 instructions. `flip_test.sh` - the only thing that decides -
  passed, and the raw objdump above shows the three words identical. **Do not read a
  `carve_diff.sh` "differs at +0" as a real mismatch without checking the raw objdump;** the tool
  is not in the carve vein's list of required steps and I did not touch it (tools/ is judge-owned).
- **`__construct_array`'s second argument is the constructor, the third is the destructor.** Two
  unrelated units disagree about which is which at first glance (`__destroy_arr(arr, dtor, size,
  count)` vs `__construct_array(arr, ctor, dtor, size, count, ctor_args)`); matching the
  `__destroy_arr` call's argument order against the `__construct_array` one in the same function
  settles it. Worth knowing before writing the next array-helper carve.
