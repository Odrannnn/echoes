## Two findings the item did not carry

**1. Retail reaches this only through a vtable, and no `bl` calls it.** `grep -rn 'bl fn_80200690'
build/G2ME01/asm/` returns nothing — no direct call anywhere in the DOL. A scan of every `.data`
word for the value 0x80200690 finds exactly one hit, at **0x803B7C40**, which is **slot 10 of
`lbl_803B7C18`** (`symbols.txt:18321`, size 0x80 = 32 entries). That table's slot 2 is
`fn_801FFEB0`, slot 3 is the named `TypesMatch__15CScriptTextPaneCFi`, slot 9 is `fn_802006B0`
— the 0x6C-byte function directly above the claim — and slots 13-30 are `CActor` members
(`PreRenderAllViewports`, `HealthInfo`, `GetTouchBounds`, `GetSortingBounds`, …). So slots 9 and
10 are this class's two unnamed `CActor` overrides, and the `bl` says which one slot 10 is. The
header records the table as evidence and states plainly that the *class* is not claimed: no unit
claims 0x803B7C18, so the table is dtk's `.data` and only its pointer is load-bearing.

**2. The callee is a `Matching` unit's own symbol, so the reference is free.**
`src/MetroidPrime/CActor.cpp:413` defines `CActor::EnsureRendered(const CStateManager&)` and
`build/G2ME01/asm/MetroidPrime/CActor.s:3234` shows the emitted
`.fn EnsureRendered__6CActorCFRC13CStateManager, global`. A `Matching` unit needs its callees'
*symbols*, not their bodies (the same point `Carve801FEC64.c` makes), so this unit declares
retail's name and defines nothing. `ScriptObjects/CIngBoostBallGuardian13E68.cpp:39` already
declares this very name for the DOL, which is the precedent.

**Port half.** The host compiler mangles `CActor::EnsureRendered` the Itanium way, so nothing in
the port defines the unmangled name. The file is `#ifndef TARGET_PC` … `#else` with an announced
no-op in the `#else`, the arrangement `Kyoto/Graphics/Carve80310E8C.c:105-148` uses. No port
source names `fn_80200690` and no port vtable is built for `lbl_803B7C18`, so nothing calls the
stand-in. It is deliberately a no-op and labelled as one, not a plausible-looking forward.
