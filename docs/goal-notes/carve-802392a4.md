- `fn_802392A4` = `fn_71_3B08` (`CSnakeWeedSwarmVecTail.cpp:212-225`), this block's `reserve`:
  `include/rstl/vector.hpp:167-179` with `mAllocator` four bytes wide, so the count is at +0x4,
  the capacity at +0x8 and the base at +0xc. `capacity <= x08` returns without allocating,

  frees the old base, stores base and capacity back.

here as eight `lwz`/`stw` pairs rather than calling an out-of-line `fn_71_B50`.

## The one non-obvious thing, and why this is a `.cpp`

The callee's first two instructions are `lwz r6,0(r3)` / `lwz r0,0(r4)`, and the caller passes
`addi r3,r1,20` / `addi r4,r1,12`. **Both iterators arrive as the address of a one-word object**,
and each is stored twice before the call - `stw r6,12(r1)` + `stw r6,8(r1)` for `end`,
`stw r0,20(r1)` + `stw r0,16(r1)` for `begin` - once into the caller's temporary and once into
the outgoing argument slot. That is MWCC's ABI for a by-value 4-byte class parameter.

**In C that shape is unreachable**: a 4-byte struct passed by value arrives in a register, so the
callee would use `r3` directly and there would be no four stores at all. Hence `.cpp` with
`extern "C"` - the name stays unmangled, which is the arrangement
`Carve80233A90.cpp` in this same directory already uses and documents. Two further things the
same header records, both measured there and both needed here:

- The iterator needs its **converting constructor** (`SHintLocIter(void* cur)`). A plain one-word
  POD passed by value is returned in `r3` and forwarded without a temporary, which loses the
  stores. A class with a constructor is not trivially constructible, so the copy goes through
  memory and MWCC emits the four stores.
- The element is four `int` members, **not** `char[16]` and not an aggregate assignment. Retail's
  eight `lwz`/`stw` pairs are a member-wise copy; `-use_lmw_stmw on` is in the project's cflags,
  so a 16-byte aggregate assignment would have emitted one `lmw`/`stmw` pair instead.

Neither `allocate__Q24rstl17rmemory_allocatorFi` (0x802FDAB8) nor `Free__7CMemoryFPCv`
(0x802CE388) nor `fn_8023935C` is defined here - all three are declared. The first two are
claimed by other DOL units and defined for the host link elsewhere in `src/`, and the third is in
this file, so the unit **adds no undefined symbol** and needs no `#ifndef __MWERKS__` stand-in.
