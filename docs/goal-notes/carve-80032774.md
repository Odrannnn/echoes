## Why this unit is a `.cpp` (and the spellings that decide its bytes)

`fn_800328A8` and `fn_80032A00` are the compiler's own member-destruction code - the string
releases are `addic. r0,r31,off / beq / addi r3,r31,off / bl internal_dereference__...Fv`, and the
`fn_800328A8` walk is `reserved_vector::destroy_elements()` with the element destructor inlined
away. **A hand-written C body cannot produce either**: a C loop with an empty body is deleted
outright, and the `addic.`-guarded member releases are not a source spelling at all. So the unit is
a `.cpp` whose bodies are written as the `delete mPtr` that `include/rstl/single_ptr.hpp:42`
defines, with the real class types from their headers, and every definition is `extern "C"` so the
`fn_<addr>` names and `__dt__11CMayaSplineFv` stay unmangled (the precedent for a `.cpp` carve is
`src/MetroidPrime/Carve8000447C.cpp`).

Three spellings were measured this run, all against retail's own instructions:

| spelling | result |
| --- | --- |
| parameter typed as the class pointer, body `delete self->mPtr` | **byte-exact** (register shape `mr r31,r4` then `mr. r30,r3`) |
| `void* selfv` + local `void** self = (void**)selfv;` before the test | self/flag swap registers, 8 differing instructions |
| `self->~single_ptr< T >()` instead of `delete self->mPtr` | a second null-test branch, 45 instructions vs retail's 44 |

The same rule applies to the plain bodies: they use the `void*` parameter directly
(`*(const void**)self`, `(char*)self + off`) rather than a local cast.

Source order is **descending by address** (`fn_80032A00` first, `fn_80032774` last) because
mwcceppc emits definitions in reverse source order; the object comes out in retail's own order.
