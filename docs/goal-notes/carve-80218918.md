It is the Ing module's loader setter: store the handed-over pointer into the module's `.sbss`

one instruction pair.

## Why `.c`, and why the name is fixed

`config/G2ME01/symbols.txt:9467` gives the symbol as `fn_80218918` — Ing is one of the
526-of-535 whose retail names are `fn_<offset>` — and the module imports exactly that name:

```
$ strings build/G2ME01/Ing/Ing.plf | grep 80218918
fn_80218918
```

So it cannot be renamed (an alias is a different symbol whose call resolves to nothing), and a
`.cpp` would mangle it to something the module does not import. A `.c` unit compiles with
`-lang=c`, so the definition *is* the symbol. Plain C, no `asm`, no stub.

## What the argument is (measured, not assumed)

Both of the module's two call sites, in `build/G2ME01/Ing/asm/auto_00_00000000_text.s`:

- `RELExit` at module `.text:0xBC`, line 117 — `li r3, 0` first, so a null loader on the way out.
- `fn_29_100` at module `.text:0x100`, line 145 — stores a pointer to `fn_29_130` into the
  module's own `.bss:0x6C` record and hands that record's address over. The record is four
  bytes: `build/G2ME01/Ing/asm/auto_05_00000000_bss.s:76-79` gives `lbl_29_bss_6C size:0x4`.
  `src/MetroidPrime/ScriptObjects/CIngRel.cpp:22` spells the same reading out
  (`lbl_29_bss_6C = fn_29_130 ; fn_80218918(&lbl_29_bss_6C)`).

The store is therefore of a **record address, not a loader**. The one reader confirms it:
`LoadIngs`, in the `Matching` unit `src/MetroidPrime/ScriptLoader/Ings.cpp`, reads the slot as
`(*gLoader_Ings.value)(mgr, input, info)` — it dereferences what was stored here and calls
through it. That is also recorded at `CIngRel.cpp:51-52`. The struct tag names the parameter and
that shape; nothing in this unit reads through it, and the tag is declared at file scope
because a tag first seen in a prototype is scoped to that list and the host build then rejects
the definition as a conflicting type.

**The slot belongs to `Ings.cpp`, so this unit claims `.text` only.** `gLoader_Ings` is
`.sbss 0x804193D8..0x804193E0` — 8 bytes, the `value` pointer plus the `padding` word
`SLoaderSlot` declares (`Ings.cpp:11-16`) — claimed and defined by
`MetroidPrime/ScriptLoader/Ings.cpp`, whose `.text` ends exactly at 0x80218918. Declaring it
`extern` keeps it defined in exactly one unit; MWCC does not encode a variable's type in its
name, so the declaration resolves to `gLoader_Ings` itself whatever the type is spelled, which
is what `Carve802188E4.c` already does for `gLoader_DarkSamus`.
