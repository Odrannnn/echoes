### Measured: the language had to be C++, and three spellings are load-bearing

The item's rule is "plain C so the `fn_` names do not mangle". The names are kept unmangled by
`extern "C"`, but **this unit is a `.cpp`**, because a `.c` version of the same bodies does not
reach the bytes. All three of these were compiled and read back with `objdump`:

| spelling | what MWCC emitted instead |
| --- | --- |
| `int noResult = 0; ... = 1;` (`.c`) | flag hoisted out of the loop as `li r7,0` **before** the first load, tested `cmpwi r7,0`. Retail keeps it in `r5`, materialises `li r5,0` **after** the loop and tests `clrlwi. r0,r5,24` - MWCC's code for a `bool`. Same 31 instructions, 4 in the wrong place. |
| `ScriptIdConstIter` as a POD struct returned by value (C++) | returned in `r3`/`r4`: `stw r3,8(r1)` / `stw r4,12(r1)`, **14 instructions / 56 bytes** instead of retail's 19 / 76. |
| `return it;` instead of `return ScriptIdConstIter(it);` | 19 instructions and 76 bytes either way, but the epilogue restores `r31` / `r30` / `lr`; retail restores **`lr` first**: `lwz r0,0x14(r1)` / `lwz r31,0xc(r1)` / `lwz r30,0x8(r1)` / `mtlr r0`. 3 wrong words. |

So: the constructor on `ScriptIdConstIter` is what forces the return through the hidden pointer
(`r3` is the result pointer from `mr r30,r3` at 0x80233AAC to `stw r0,4(r30)` at 0x80233AC0), and
the explicit copy-construction is what orders the epilogue. The twin has both
(`const_iterator(node*, const header*, bool)` at `include/rstl/red_black_tree.hpp:78-79`, and
`return CStateManager::TIdList::const_iterator(it)`). Neither is decoration.

### The lesson worth the lane's time: `tools/carve_diff.sh` is not an independent check

`tools/carve_diff.sh <start> <size> <ours.o>` reads its "retail" side from
`build/G2ME01/main.elf`, and `build.ninja:28253` is `build build/G2ME01/main.elf: link ...` -
**that file is our own link output.** Once a unit is a `Matching` one, the tool compares the unit
with itself. It reported `retail: 50 instructions, 200 bytes / ours: 50 instructions, 200 bytes /
differing instructions: 1 / NOT byte-exact` on a build whose `main.dol` still differed from the
disc in **8 bytes / 3 words** (the epilogue order above). The independent check is a word diff
against `orig/G2ME01/sys/main.dol` (`.text` is at file offset `vaddr - 0x80003200`) or
`sha1sum build/G2ME01/main.dol`. A throwaway that does this is in `.tmp/opencode/trial.sh`
(one mwcceppc run + a disc diff, ~0.1 s, versus a 3-minute `decomp_build.sh`).
