## The `.cpp` with `extern "C"`, not the `.c` the seed named

The seed said "plain C so the fn_ names do not mangle". Plain C cannot spell the callee:
MWCC mangles `rstl::vector<float>::vector(CInputStream&, const rmemory_allocator&)` as
`__ct__Q24rstl36vector<f,Q24rstl17rmemory_allocator>FR12CInputStreamRCQ24rstl17rmemory_allocator`,
and `<`, `>`, `,` are not identifier characters. The documented dodge is closed -
`extern void f(...) asm("<mangled>")` is rejected by mwcceppc in both C and C++
(already measured, `src/MetroidPrime/Carve801285DC.c:47-48`). So the unit is a `.cpp` whose one
definition is `extern "C"`, which is what keeps `fn_802553F4` verbatim; the arrangement
`src/MetroidPrime/Carve8024492C.cpp` and `src/MetroidPrime/Carve801EF730.cpp` already use for
Matching carves, and both of those also return a class by value.

## The thing that made it work: an explicit specialization declaration

`include/Kyoto/Streams/CInputStream.hpp:196-203` **defines** the stream constructor (`inline`,
right after the `Get` templates). Compiling the body with that header included gives, measured:

```
$ <mwcceppc GC/2.7, the build's own flags> -c probeA.cpp
00000000 T fn_802553F4
00000024 W __ct__Q24rstl36vector<f,Q24rstl17rmemory_allocator>FR12CInputStreamRCQ24rstl17rmemory_allocator
000000c8 W reserve__Q24rstl36vector<f,Q24rstl17rmemory_allocator>Fi
         U ReadFloat__12CInputStreamFv
```

`fn_802553F4` itself is still the right nine instructions, but mwcceppc also emits a **weak
out-of-line copy of the constructor and of `reserve`** into this object - two symbols retail's
object for this claim does not define, and the `bl` would then resolve to that local copy instead
of to retail's 0x80255418.

The fix is one declaration, and it is the general recipe for "call a retail template
instantiation out of line without dragging a copy into your object":

```cpp
#include "rstl/vector.hpp"          // declares the member, does NOT define it
namespace rstl {
template <>
vector< float >::vector(CInputStream&, const rmemory_allocator&);   // declared, never defined
}
```

Including only `rstl/vector.hpp` (whose line 52 *declares* the member) plus an explicit
specialization declaration turns the call into an external reference. Measured on the same flags:

```
$ nm probeB.o
         U __ct__Q24rstl36vector<f,Q24rstl17rmemory_allocator>FR12CInputStreamRCQ24rstl17rmemory_allocator
00000000 T fn_802553F4
$ objdump -h probeB.o        # one section: .text 0x24
```

## Why the claim is where it is

`fn_802553F4` is 0x2CC bytes **into** dtk's `auto_03_80255128_text` (0x80255128..0x802554BC) and
ends exactly where the next function begins, `__ct__Q24rstl36vector<f,...>` at 0x80255418
(`symbols.txt:10474`, 0xA4). So the claim absorbs neither neighbour, spans no unclaimed gap, and
starting 0x2CC bytes in - rather than at the auto range's first byte - is what keeps `dtk dol
split` from reporting a link-order cycle. After the split dtk emits
`auto_03_80255128_text.s` (0x80255128..0x802553F4) and `auto_03_80255418_text.s`
(0x80255418..0x802554BC); the carve's own object carries one section, `.text` 0x24. The
directory is retail's own, taken from the nearest claimed ranges: below
`WorldFormat/CAreaRenderOctTree.cpp` (0x80254BAC..0x80255128), above
`WorldFormat/Carve802554BC.c` (0x802554BC..0x802554D0).

## What the function is

Its twin is `CInputStream::Get<rstl::basic_string<char, rstl::char_traits<char>,
rstl::rmemory_allocator>>` at 0x80051FC4, 0x24, weak
(`build/G2ME01/asm/MetroidPrime/CWorld.s:4253-4263`) - nine instructions word for word, and the
same `bl` encoding `48 00 00 15` only because the callee happens to sit 0x14 bytes past the `bl`
in both. That twin function measures **100.0%** in `build/report.json`, whose entry also carries
its demangled name - `CInputStream::Get<rstl::basic_string<...>>(const TType<...>&)` - which
confirms the identification independently. **Its unit is `NonMatching`, though**:
`main/MetroidPrime/CWorld` is 89.58%, so the file's header says the twin scores 100.0% *per
function*, not that it sits in a `Matching` unit. Its source is
`include/Kyoto/Streams/CInputStream.hpp:117-120`:

```cpp
template < typename T > inline T CInputStream::Get(const TType< T >& type) { return T(*this); }
```

So the shape is "construct a `T` from the stream, hand it back by value". Here `T` is
`rstl::vector<float>`, and that is settled by two measurements, not by the shape:

1. the callee's own retail name at 0x80255418; and
2. the **only** caller in retail, `grep -rn "bl fn_802553F4" build/G2ME01/asm/` ->
   `build/G2ME01/asm/auto_03_80255128_text.s:208`, 0x8025539C inside `fn_80255370` (0x80255370,
   0x84), which reaches it with `addi r3,r1,0xc` (its own frame's `rstl::vector<float>`
   temporary) and `r4` = `r31`, the stream it saved at 0x80255384 from its own `r4`, and then
   hands the same `r1+0xc` to `fn_8015B780` at 0x802553A8.

`r3` is therefore the sret slot, and the callee's first three stores (`stw r0,4(r3)` / `8(r3)` /
`c(r3)` at 0x80255440-0x80255448) go straight into the caller's temporary. `addi r5,r1,0x8` is
the default `rmemory_allocator` argument's temporary - `rstl::vector`'s allocator is the empty
type, so it is never written, only its address passed, which is why the frame is 0x10 bytes.
