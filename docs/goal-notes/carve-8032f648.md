## The finding that made it byte-exact: `void* const*` parameters

The twin is a template (`CIOWinManager.s`'s `erase`/`clear`), and my first four C spellings all
compiled to the right *length* (25 instructions) with both loads in the wrong *place*, i.e. a
0-byte match at 25/25 instructions. Retail's `fn_8032F688` prologue interleaves the loads with
the register-save block:

```
stw r0,0x24(r1) / lwz r0,0(r5) / stw r31,0x1c(r1) / lwz r31,0(r6) / stw r30,0x18(r1) / mr r30,r4 ...
```

while `void**` parameters give the whole save block first and both loads after:

```
stw r0,0x24(r1) / stw r31,0x1c / stw r30,0x18 / mr r30,r4 / stw r29,0x14 / mr r29,r3 / lwz r0,0(r5) / lwz r31,0(r6)
```

Adding the **`const` to the pointee** (`void* const*`) is the entire fix, measured on this body:
`void**` -> saves first; `void* const*` -> retail's order. The twin gets the same thing from
`const iterator&` being a reference to a const object, so this is a general MWCC rule worth
remembering, not a spelling accident.

I also checked whether C++ was needed, since the twin is C++: an `extern "C"` copy with a class
`iterator` (user-provided constructor, `operator!=`) and `const iterator&` parameters reaches the
same bytes. It is not needed - the plain-C form above does - so the unit stays a `.c`, which is
what the `fn_` names need. The C++ probe is recorded because it is the evidence that the C form is
not a coincidence.

## `fn_8032F648`: two orderings in tension

Retail's `clear` loads `+0x8` and stores it to 0x8 **before** loading `+0x4` and storing it to
0xc, and passes `&0xc` in `r5` and `&0x8` in `r6`. Two different orders are involved and only one
spelling satisfies both:

- the **stack slots** follow declaration order - arg 3 (`start`) must land at 0xc and arg 4
  (`end`) at 0x8, so `start` has to be declared first;
- the **loads** follow statement order - `end` has to be assigned first.

Written as one declaration `void* start = list->x4_begin, void* end = list->x8_end;` the slots are
right and the loads backwards; swapping the declarations fixes the loads and breaks the slots
(both measured). The shipped body therefore declares both and assigns them in the other order.
Also measured and rejected: passing `&list->x4_begin` directly, which drops both temporaries and
both loads.
