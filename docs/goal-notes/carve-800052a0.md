## Spellings: two of the three took iteration, both worth keeping

`fn_800052A0` and `fn_800052E0` were byte-exact on the first successful compile. `fn_80005310`
needed three changes, and two of them are general:

| spelling | result |
| --- | --- |
| `struct SNode* const root = ...` as the **first** statement of the body | **Error: expression syntax error.** This compiler's C mode is C89 for declarations: a declaration after the three null stores is a syntax error, and `root` has to be declared *after* them (retail's order) |
| `struct SNode* const root;` then `root = ...;` | **Error: illegal assignment to constant.** `const`-pointer in C mode is initialiser-only, unlike C++ |
| `struct SNode* const root = ...;` at the top of the body, then the stores after | compiles, but the three null stores then land *after* the `bl`, and the `lwz r4,0x10(r4)` argument load is 6 instructions late - **43 of 70 differ** |
| the same declaration wrapped in its own `{ }` block after the stores | **byte-exact.** The `const` on `root` is still load-bearing (it is what keeps the `cmplwi r3,0 / mr r4,r3 / beq` from collapsing into the inlined `Leftmost`'s record form), and the block is what lets the declaration sit after the stores in C89 |
| `static struct SNode* Leftmost(...)` / `Rightmost(...)` (no `inline`) | both **outlined**: 76 instructions / 304 bytes, and `unit_fit` would list two extra functions. `-inline deferred,noauto` means nothing is inlined unless it says `inline` |
| `static inline struct SNode* Leftmost(...)` / `Rightmost(...)` | **byte-exact: 70 / 70, 3 differing `bl`s** |

**So the general lesson: a C carve that needs an out-of-line helper written as a member of a C++
class must add `static inline` explicitly here, and a C carve that needs a `const` local after
statements must wrap it in a block.** Neither is a spelling preference; each is a hard error or a
wrong object.

## The one thing this run found that five earlier runs did not record: the probe compiles a carve `.c` as C++

The first `goal_check.sh` run **FAILED** on this run's own tree, and not on anything about the
carve:

```
  FAIL  gate.sh
        GATE FAIL: probe
```

`./tools/probe_sources.sh` then reported `800 files, 1 failed`, naming this run's new file, and
`build/probe-logs/src_MetroidPrime_Player_Carve800052A0.c.log` holds the reason:

```
src/MetroidPrime/Player/Carve800052A0.c:149:43: error: invalid conversion from 'void*' to 'SNode*' [-fpermissive]
```

**`tools/probe_sources.sh:78` sends every `src/**.c` that is not `src/LZO/*.c` and not
`platform/glibc_compat.c` to `g++ $CXX_FLAGS` with `-std=c++20`** - a carve `.c` is syntax-checked
as C++, not as C, even though mwcceppc compiles it with `-lang=c`. So a carve `.c` has to be valid
in *both* dialects, and the two pull in opposite directions:

| construct | MWCC `-lang=c` | `g++ -std=c++20` probe | what this run used |
| --- | --- | --- | --- |
| `NULL` | **undefined identifier** (`Error: undefined identifier 'NULL'`, aborts the build) | fine | `0` |
| `void*` returned into a node pointer | fine (implicit in C) | **hard error** | `struct SNode* fn_80008C28(...)`, the type `main.cpp:346` already gives it |
| declaration after statements | **syntax error** (C89) | fine | the `{ }` block the first run found |
| implicit conversion into a `const` local initialiser | fine | fine | unchanged |

So the general rule, in one line: **in a carve `.c`, declare an extern's return type as the type
the real definition uses rather than as `void*`.** It is the same declaration either way at the
assembly level - the callee's result lands in `r3` regardless - so the object was byte-identical
before and after the change, but only the second spelling survives the probe. No earlier run of
this item recorded this, which is why five runs of a passing item still left it undiscovered: each
one drove `goal_check.sh` from a source that happened not to need a `void*` result.

The other half of the finding is the ordering. `probe_sources.sh` is part of `gate.sh`, which is
part of `goal_check.sh`, so this is a **late** failure - it costs a full gate run (~90 s) after the
build and link are already green. For any new carve `.c`, run `./tools/probe_sources.sh` directly
before `goal_check.sh`; it takes a few seconds and names the offending file and line.
