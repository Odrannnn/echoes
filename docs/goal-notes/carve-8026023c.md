## The two bodies, and what the bytes fixed rather than suggested

`fn_802602E0` is the twin forwarder: `return fn_8026030C(obj);` over the class return. That is the
whole function.

`fn_8026023C` is the twin's constructor, and four things about it are **not** free choices:

1. **The receiver is r3 and is returned.** `mr r31,r3` at 0x80260258 and `mr r3,r31` at 0x802602CC
   are the sret convention for a constructor, so the member stores are `stb r0,0x0(r31)` and
   `stw r3,0x4(r31)` and `self` must come back in r3. Modelling it as a `void` function loses the
   last instruction and the function is 0xA0 instead of 0xA4 (measured).
2. **The argument temporary is an `rstl::auto_ptr<T>` built from a raw pointer.** The
   `neg r0,r4 / or r0,r0,r4 / srwi r0,r0,31` at 0x80260248-0x80260254 is its `mHas =
   (ptr != nullptr)` and the `stw r4,0x14(r1)` beside it is its `mItem` — the header's
   `auto_ptr(T* ptr) : mHas(ptr != nullptr), mItem(ptr)`.
3. **The two temporaries must be different types.** Both teardowns read `if (mHas) delete mItem`,
   but retail inlines the result's and calls the argument's out of line as `fn_802603A8`. Giving
   them one type makes mwcceppc inline both, and the function becomes 0xD0 bytes ending in
   `Free__7CMemoryFPCv` instead of in `fn_802603A8` (measured). This is the finding worth keeping:
   *which* teardown is out of line is not cosmetic, it is 0x2C bytes and a different callee.
4. **The member stores must be inside the same full-expression as the call.** Written as two
   statements, the temporaries are destroyed first and the whole 0x34-byte tail moves (measured).
   Hence the `ctor()` helper taking the released pointer. It returns **void** and takes the item
   **by value**: returning the receiver as well makes mwcceppc keep a second live copy in r30
   (`stw r30,0x18(r1)` / `mr r30,r3`), two instructions retail does not have, 0xA8 bytes
   (measured).

Two further measured spellings that do **not** work, so the next run does not spend a session on
them: this compiler has no aggregate initialiser (`SArgPtr{a, b}` is a syntax error — give the type
a constructor and write it inline in the call, or a *named* local adds an `stw r30` / `mr r30,r3`
pair and 0xA8 bytes); and `extern "C"` on a constructor is rejected (`illegal storage class`).

## Notes for the next lane

- `src/Weapons/Carve8026023C.cpp` is a `.cpp` with `extern "C"`, **not** a `.c`. The seed's advice
  and `src/Dolphin/Carve8038A7DC.c`'s "the definitions have to stay C" are both right about the
  names and wrong about the file for this pair. Record it next to
  `src/MetroidPrime/Carve801EF730.cpp:99-110`.
- A carve out of an `auto_*` run whose *first* claimed function's predecessor ends exactly at the
  claim's start is safe: `fn_802601D0` ends at 0x8026023C and the claim begins there. The cycle
  `docs/RUNNING_THE_DECOMP.md` warns about is a claim starting where a *unit*'s `.text` ends, and
  `fn_802601D0` is inside the same `auto_*` run, so it is not a unit boundary. Proximity to a
  claimed *range* is fine; proximity to a claimed *unit* is what breaks `dtk dol split`.
- `tools/gate.sh` rewrites `docs/HANDOFF.md` and `docs/RUNNING_THE_DECOMP.md` when
  `MP_GATE_DOCS_WRITE=1` (which `goal_check.sh` sets), so those two files show up modified after a
  judge run with only derived counts changed. Reverted here; the driver discards them anyway.
- Two helpers earned their keep and are worth keeping in `.tmp/opencode` for the next lane (both
  removed, both trivial to rebuild): compile one scratch `.cpp` with the unit's exact `build.ninja`
  flags and print our symbols beside retail's (`tools/probe_cc.sh` does this), and compare two
  named functions word for word with `bl` displacements masked — **extents from `nm -S`, not from
  the label stream**, because our object interleaves other functions between the two we claim and
