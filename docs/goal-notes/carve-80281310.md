**Verdict: the unit flips.** `tools/flip_test.sh MetroidPrime/Carve80281310.c` prints `PASS -> kept
as Matching`, `main/MetroidPrime/Carve80281310` is 100.00% fuzzy / 2 of 2 functions matched /
`complete`, `main.dol` is `6ef9b491d0cc08bc81a124fdedb8bfaec34d0010`, and

`matched 12530 -> 12532   linked 5903 -> 5905`.

**The other two functions in the seed cannot be written, and the reason is measured, not a
shortage of effort.** `fn_8028139C` and `fn_802813C4` each have exactly one `bl`, and both targets
are MWCC-mangled C++ template symbols. There is no way to name them from a `.c` unit. Details, with
the commands, are in "The wall" below.

Both written bodies are byte-identical to a **named** retail symbol elsewhere in the DOL, which is
what makes them worth claiming:

- `fn_80281310` is instruction-for-instruction
  `uninitialized_fill_n<rstl::vector<CToken>*, rstl::vector<CToken>>`, at
  `build/G2ME01/obj/MetroidPrime/CGameArea.o:0x9928` - same 27 instructions, same frame, same

  pre-test at the bottom with `b` over the body. Its `construct(&*cur, value)` is this carve's
  `fn_8028137C`, and its third argument arrives in `r5` as the *address* of the value, which is
  why `fn_8028137C`'s second parameter is a pointer and not a value. `fn_8028137C` is the
  forwarding half of the same pair - the shape of `__sys_free` (`src/MetroidPrime/main.cpp:396`).

## The wall: no C declaration can name a MWCC-mangled symbol

`fn_8028139C`'s only call is
`bl "__ct__Q24rstl37vector<Pv,Q24rstl17rmemory_allocator>FRCQ24rstl37vector<Pv,Q24rstl17rmemory_allocator>"`
(retail 0x8005C2D4, `config/G2ME01/symbols.txt:1811`, 0x100 bytes). `fn_802813C4`'s only call is
`bl allocate__Q24rstl17rmemory_allocatorFi` (retail 0x802FDAB8, `symbols.txt:13824`, 0x3C bytes).
Both target names contain `<`, `>` and `,`, which a C identifier cannot, and mwcceppc has no
alias syntax. Measured, with the version `configure.py` selects:

```
$ cat > /tmp/t1.c <<'EOF'
extern void ctor_alias(void* self, const void* src) __asm__("__ct__Q24rstl37vector<Pv,Q24rstl17rmemory_allocator>FRCQ24rstl37vector<Pv,Q24rstl17rmemory_allocator>");
void f(void* p, const void* q) { ctor_alias(p, q); }
EOF
$ wibo .../compilers/GC/2.7/mwcceppc.exe <the cflags from build.ninja> -c /tmp/t1.c -o /tmp/t1.o
#       1: extern void ctor_alias(void* self, const void* src) __asm__("__ct__Q24rstl37vector<Pv,Q24rstl17rmemory_allocator>FRCQ24rstl37v
#   Error:                                                             ^
#   type cannot be made into a global register variable;
#   only scalers, doubles, floats and vectors are supported.
```

The same error with `asm(...)`, in a `.cpp`, and on an `extern "C"` function - three spellings,
one result, in both language modes. And an explicit specialization declared without a definition
cannot be called at all:

```
$ cat > /tmp/t5.cpp <<'EOF'
template <class T> void g(T* p, const T& q);
template <> void g<void*>(void** self, void* const& src);
void fn_x(void** self, const void* src) { g<void*>(self, src); }
EOF
#   Error:  function call 'g(void **, const void *)' does not match 'g<...>(T0 *, const T0 &)'
```

The remaining spelling - let mwcceppc *define* the instantiation, by writing the real
`rstl::vector<void*, rmemory_allocator>` copy constructor - is worse: mwcc emits its own out-of-line
copy of it in the calling TU, which is 0x100 bytes of a function retail keeps at 0x8005C2D4.
`tools/unit_fit.sh` reports that as an extra function and no claim can absorb it, since the bytes
would land in the middle of this unit's range.

This confirms, for a second time and from the other direction, the finding already recorded at
`src/MetroidPrime/main.cpp:1176-1177` ("It cannot be *declared*, because a C++ identifier cannot
contain `<` or `>`, and `__asm__("...")` after a declarator is rejected by this compiler, so there
is no spelling of the call that names it"). **A carve unit that has to reach a MWCC-mangled symbol
cannot be written at all** - that is a general limit of the vein, not of these two functions, and
it is worth the seeder knowing before it plans four adjacent functions whose only call target is a
template instantiation.

No `WALL:` line: the item passes, and this is not a sub-100% spelling search - there is no spelling
to score. No `NEW:` line either: no untried approach is left that would raise a count, and a
`NEW:` costs a lane an hour.

## The port

`fn_8028137C` forwards to `fn_8028139C`, which is unclaimed, so the carve declares it and never
defines it - and listing the carve in `files.cmake` therefore put `fn_8028139C` in the host link's
undefined set, which `tools/link_check.sh --strict` fails on (the pattern is the one
`docs/goal-notes/carve-800e1548.md` paid for with `fn_800E0B80`). So
`src/MetroidPrime/PortGlobals.cpp` gained the host body: retail's bytes are
`cmplwi r3,0 / beq` then the copy constructor of `rstl::vector<void*, rmemory_allocator>`, whose
definition is already in `include/rstl/vector.hpp:127-136`, so the body placement-news that
constructor and does nothing on the null path. It is the real work, not a stand-in: no pixel, no
return value, no stub that announces itself.
