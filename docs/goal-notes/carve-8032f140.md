### What actually decided the source, and it is the interesting part

Retail's 0xB0 tail is **three instructions longer** than `fn_8028E820`'s 0xA4, and the difference
is not noise — it is the whole of the outer temporary's teardown:

```
retail 0x8032f1c0   lbz r0,0x10(r1) / cmplwi r0,0 / beq      ; if (local.mHas)
retail 0x8032f1cc   lwz r3,0x14(r1) / li r4,1 / bl fn_8032F2B8
twin   0x8028e8a0   addi r3,r1,16 / li r4,-1 / bl fn_8028ED18
```

So **here** the `rstl::auto_ptr<T>` temporary's destructor is *inlined* and hands the **owned
pointer** to a *deleting* call; **there** it was emitted out of line and handed the `auto_ptr`
itself with the non-deleting flag.  That is the difference between
`~auto_ptr<T>()` (`if (mHas) delete mItem;`, inlined) and an out-of-line
`__dt__...Fv` (`this` = the object, flag = -1).  Consequence for the spelling:

**`rstl::auto_ptr<T>` cannot be used for the outer temporary.**  Its destructor would emit
`delete mItem`, and `delete` on a `T*` the compiler cannot devirtualise is *not* the direct
`bl fn_8032F2B8(mItem, 1)` retail has.  The carve therefore uses a local class with
`rstl::auto_ptr`'s layout and a **trivial destructor** (`SOwnedPtr` in the file), and writes the
`if (local.mHas) fn_8032F2B8(local.mItem, 1);` out by hand.  Its *constructor* is
`rstl::auto_ptr`'s member for member, because the order of the three stores is what fixes
0x8032F14C..0x8032F16C.

The **inner** temporary — the `rstl::auto_ptr<IObj>` `fn_8032F1F0` returns — is left as the real
class, because that one *is* `rstl::auto_ptr<IObj>::~auto_ptr()`: `if (mHas) delete mItem;` with
`mItem` an `IObj*` whose destructor is virtual (`include/Kyoto/IObj.hpp:14`), which compiles to
retail's exact nine instructions (null test, `lwz r12,0(r3)`, `li r4,1`, `lwz r12,8(r12)`,
`mtctr`, `bctrl`).  Getting that required `#include "Kyoto/IObj.hpp"`; it is not a guess.

The member stores had to stay in the **same full expression** that built the temporaries
(`obj->mItem = (obj->mHas = (p = fn_8032F1F0(local).release()) != nullptr, p);`).  `p` must also be
a separate local, because `fn_8032F1F0(local).release()` is not a `T*` — `SOwnedPtr` is not
convertible to `IObj*`, and the release has to return the `IObj*` the token owner holds.  Both of
these are the orderings `src/Kyoto/Animation/CAnimCharacterSet.cpp:416-423` already measured; the
split-statement version is 46.32%.

### `.cpp` with `extern "C"`, not `.c`

The seed said plain C "so the fn_ names do not mangle", and the concern is right, but it is not
possible here.  `fn_8032F1F0` returns a **class**, so MWCC passes a hidden result slot in r3 and
keeps it in the callee-saved r31 across the call — that `mr r31,r3` plus its `stw`/`lwz` pair is 3
of retail's 11 instructions.  A plain-C function returning an 8-byte POD is handed back in
`r3:r4` and never touches r31: **8 instructions, not 11**.  That is measured and already recorded at
`src/MetroidPrime/Carve801EF730.cpp:99-110`, which is the arrangement I followed (same unit
pattern, same `extern "C"` wrapper, same `#ifndef __MWERKS__` stand-in convention).  `fn_8032F140`
also needs C++: it returns `self`.

## Reusable (a lesson, not a `NEW:` item)

**A byte-shape twin can differ from its twin in exactly one place, and that one place decides the
data model of the whole carve.**  Here the seed's two twins are the *same C++ function* written
twice, yet one inlines the temporary's destructor and hands `mItem` to a deleting call while the
other calls an out-of-line `__dt__...Fv` with `this` and flag -1.  Nothing about the call graph
says which; only the three tail instructions do, and they rule out using the real
`rstl::auto_ptr<T>` for that temporary even though every other part of the function is written in
terms of it.  Read the *tail* of a twin before choosing the type, not just the body.

Second, reusable: **`tools/dis.sh` on the twin pair is the cheapest possible first step** — it
found the 12-byte tail difference before any code was written, and `fn_8028E820` (already
`Matching`) then handed over the whole spelling.
