## What it is, measured

`fn_80255350` is a **byte-shape twin** of `fn_80004438` (`rstl::destroy< CWorldState >`,
`src/MetroidPrime/Carve80004438.c`, `Matching`): the same 32 bytes word for word, only the `bl`
target differing. Its source there is one statement, `fn_80004458(self)`, so the body here is one
statement too.

**But it is not a `destroy`, and the header says so.** The seed's twin is `destroy_impl(T*, int)`
and materialises a `li r4,-1`. `fn_80255370` does not: it reads `r4` as a `CInputStream`
(`mr r31,r4` 0x80255384, `lwz r4,0x8(r31)` / `lbz r4,0x0(r4)` 0x802553B8/0x802553C8) and `r5`
as the allocator it forwards as the third argument to `fn_802553F4` (`addi r5,r1,0x8` then
`mr r30,r3` / `bl fn_802553F4` / `mr r3,r30` / `bl fn_8015B780` /
`bl __dt__Q24rstl36vector<f,Q24rstl17rmemory_allocator>Fv`, and `stb r0,0x10(r30)` for a flag
byte out of the stream). So `fn_80255370` is retail's out-of-line
`rstl::vector<float>`-from-`CInputStream` element load, and this function is a plain out-of-line
**forwarder for three arguments**, written as three `void*` parameters. One caller fixes the
arity: `grep -rn "bl fn_80255350" build/G2ME01/asm/` returns exactly 0x8025531C inside
`fn_802552E4` (`auto_03_80255128_text.s:153-181`), reached with `addi r3,r1,0xc`, `addi r5,r1,0x8`
and the stream still in `r4`, having just stored `lbl_80419714` (a `size:0x1` object,
`symbols.txt:20845`) into `0x8(r1)` — the `rmemory_allocator` temporary the third argument points
at.

The same out-of-line tail-call idiom appears three more times in this unclaimed run:
`fn_802552A4` (0x20, `bl fn_801E1738`), `fn_802552C4` (0x20, `bl fn_802552E4`) and `fn_802553F4`
