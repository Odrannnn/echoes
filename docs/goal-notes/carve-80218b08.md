## What I measured

`fn_80218B08` is `stw r3, gLoader_Blogg@sda21(r0)` / `blr` (`90 6D 96 90 4E 80 00 20`), 0x8 bytes.

`Carve802189D0.c`); the three differ only in the `@sda21` displacement, since their slots are
`gLoader_SpacePirate` 0x80419358 = `95 D8`, `gLoader_Blogg` 0x80419410 = `96 90`,
`gLoader_SandBoss` 0x804193E0 = `96 60`. No spelling had to be discovered.

- Callers read off `build/G2ME01/Blogg/asm/MetroidPrime/ScriptObjects/CBloggRel.s`:
  `RELExit` at 0x94 (0x24 bytes, `li r3,0` / `bl fn_80218B08`) passes null; `fn_7_D8` at 0xD8
  (0x30 bytes, from `RELMain` at 0xB8) does `lis r4,fn_7_108@ha` / `lis r3,lbl_7_bss_10@ha` /
  `addi r0,r4,fn_7_108@l` / `stwu r0,lbl_7_bss_10@l(r3)` / `bl fn_80218B08` with `r3` still on
  `lbl_7_bss_10`. So the argument is that record's address.
- Record is **4 bytes**: `config/G2ME01/rels/Blogg/symbols.txt:393` gives `lbl_7_bss_10 =
  .bss:0x00000010; size:0x4 data:4byte`, and `build/G2ME01/Blogg/asm/auto_05_00000000_bss.s` is
  the same 4 bytes. So the bare-function-pointer spelling of `Carve80200F30.c` /
  `Carve802189D0.c`, not module 72's 0x1C-byte struct.
- Slot `gLoader_Blogg` is `.sbss 0x80419410` (`config/G2ME01/symbols.txt:20715`,
  `type:object size:0x8 data:4byte`), already claimed and defined by `Blogg.cpp` as
  `SLoaderSlot { FScriptLoader* value; unsigned int padding; }`, whose `LoadBlogg` reads `+0`.
  This unit claims `.text` only and takes the pointer as `extern`.
