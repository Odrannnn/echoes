## The fifth file, and why it is not optional

Listing a carve in `files.cmake` puts the name of every `extern` it declares into the port link's
undefined set. `tools/gate.sh`'s `link-gap` step fails on a symbol that is missing and not already
in `docs/research/port_link_gap_list.md`, and I may not edit that file - so the callee needs a
definition on the host. `fn_80178AD0` had none: `src/MetroidPrime/CMemoryCard.cpp` **is** in the
port build (`files.cmake:1434`) but its object does not define the symbol, exactly as its header
says.

So `src/MetroidPrime/PortGlobals.cpp` gained the same trade `fn_8028139C` and `fn_8012862C` already
make there - an announced, empty stand-in that prints its own name once:

```c
extern "C" void fn_80178AD0(void*, void*, void*) {
  static bool reported = false;
  if (!reported) { reported = true;
    printf("port stand-in reached: fn_80178AD0 - the real body is not written\n"); }
}
```

`PortGlobals.cpp` is not a unit in `configure.py`, so the definition cannot reach `main.dol`. Retail's
body is quoted in the comment above it (build a `rstl::basic_string<char,...>` from the stream into
an `0x8(r1)` frame temporary, then three cursor-advanced `uint` reads into `self+0x10/+0x14/+0x18`),
so the file says what it does not do. Verified: `tools/link_gap.py`'s `MISSING` bucket stayed at
**278**, and `probe: 1018 files, 0 failed, 0 errors; link: LINKED (286 undefined, 0 duplicates)` -
the gap did not grow, and `duplicate definitions 0` (no `PortLinkStubs.cpp` duplicate existed for
either symbol; `grep -rn "fn_801832E8" src include` found nothing before this change).
