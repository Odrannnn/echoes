## The codegen fact that cost the one iteration: the destroy loop's **double null test**

`fn_80213320`'s inline destroy loop is retail's `cmplwi rX,0 / beq / beq / mr r3,rX / bl`. A
hand-rolled `for` over `Elem*` emits **one** `beq`. The source that emits two is the header's
`rstl::destroy(begin, end)` (`rstl/construct.hpp`) over an element whose destructor is the
**implicit destructor of a derived class** — which is exactly what `ncrc_ptr<T>` is
(`rc_ptr<T>`'s two words plus a base destructor). Measured in scratch compiles of the same loop:
class with its own destructor → 21-instruction function, one `beq`; derived class with an
implicit destructor → 22, two `beq`s. So the file spells the element as
`SCarve80213320ElemBase` (two words + `~...() { fn_8020D278(this); }`, inline so it never reaches
the object) and `SCarve80213320Elem : SCarve80213320ElemBase`, and calls `rstl::destroy` rather
than hand-rolling the loop. Nothing else in the file depends on the headers.
