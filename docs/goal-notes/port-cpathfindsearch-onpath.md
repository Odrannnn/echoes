`splits.txt`, no carve, no asm.

- **`src/MetroidPrime/PathFinding/CPathFindOnPath.cpp`** (new, 5 functions). `CPathFindSearch::OnPath`

  CVector3f const&, uint, uint, bool)`, `CPFArea::GetOctreeRegionList`, `CPFAreaOctree::GetRegionList`,
  `CPFAreaOctree::GetChildIndex`. **Every body is copied verbatim from the decompilation that
  already wrote it** - `CPathFindSearch.cpp:360` for `OnPath`, `CPathFindArea.cpp:64/79/211/218` for
  the other four. Nothing was re-derived, simplified, or stubbed for the host.

**Why a closed-group file and not `CPathFindSearch.cpp`.** That unit is `NonMatching`
(`configure.py:535`), 26728 bytes, and `tools/check_files_cmake.py`'s EXCLUDED entry measures
listing it at **+12 symbols opened, 0 closed** - a net rise. `CPathFindArea.cpp` is measured at
+8. Both are already excluded for that reason. The port's pattern for this is one closed group
per file (`CGameAreaSetAreaAttributes.cpp`, `CGrappleArmReturnToDefault.cpp`), and the thing that
has to fit in the file is the function's **closure**, not the function.

**The closure stops at five** because everything else it reaches is already in the port's link:
`close_enough` from `Kyoto/Math/CloseEnough.cpp` (listed), `CPFRegion::IsPointInside` /
`GetObstructionCount` / `PointHeight` from `PathFinding/CPathFindRegion.cpp` (listed), and
`CTransform4f::TransposeMultiply` is inline in `CTransform4f.hpp`. That is why the count falls
rather than merely holding.

## Codegen / port lessons worth keeping

- **"The body is written" is not the same as "the symbol is available to the port."** This
  function was written and measured 96.29% - the obstacle was that its unit is a 26 KB
  `NonMatching` block whose *other* members open 12 symbols. `docs/research/port_link_gap.md`'s
  "what closes it" column said *matching that unit*; a closed-group file is the cheaper fix and
  the row would have hidden it.
- **Size the closure, not the function, when you carve for the port.** `OnPath` is 232 bytes and
  pulls in four more functions across two files; the other two symbols that same lane recorded
  (`CPathFindSearch::Search`, `CGameCamera::ConvertToScreenSpace`) have not been measured this way
  and their closures are larger - `Search` reaches `CPFOpenList`, `CPFBitSet`, `CPFArea::PathExists`
  and `FitThroughLink2d/3d`.
