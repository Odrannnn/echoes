## Load-bearing spellings, and where they came from

- **The loop must be an inequality between two pointers, not a count.** `rstl::destroy_impl`
  (`include/rstl/construct.hpp:100-109`) over a trivially destructible element keeps its loop with
  an empty body; written against `mCount` the compiler removes it.
- **The four stores at `+0x08/+0x0C/+0x10/+0x14` are the by-value `pointer_iterator` home slots**
  - one copy per parameter of the `destroy`/`destroy_impl` pair. That is why `Destroy` and
  `DestroyImpl` are written as two nested `static inline` functions, exactly as
  `Carve800045A0.c:127-135` does, and it is measured there: a plain pointer loop drops all four
  stores and comes out 16 bytes short.
- **Structs are declared above the prototypes, not below.** A `struct` named inside a parameter
  list is scoped to that list; mwcceppc only warns, so the matching build stays green while
  `tools/probe_sources.sh` rejects the host build.
- **`extern "C"` is not used and the unit is a `.c`.** `symbols.txt` carries the `fn_<addr>`
  placeholders and this file reproduces them verbatim, so a C++ definition would mangle to
  `_Z<len>fn_<addr>v` and objdiff would pair nothing. The file is compiled as C for the port's
  host build and syntax-checked as C++ by `probe_sources.sh`, hence the explicit casts.
