## Notes for the next run

1. **The carve-vein link-order cycle did not fire here either, which is now two for two.**
   `carve-80200e3c` recorded the same result at `SpacePirate.cpp`'s end / `0x80200E3C`. This
   carve starts at exactly `MysteryFlyer.cpp`'s `.text` end (0x80232868) and links cleanly.
   So "abutting a preceding `Matching` unit's `.text`" is not the trigger; whatever distinguishes
   the `CFrustumPlanes.cpp`/`0x80302BAC` case is not present in either of these two pairs.
   A lesson, not work - no `NEW:` line.

2. **A carve with no host block is the cheap sub-case, and the difference is measurable.**
   `Carve80227530.c` needed an `#ifndef __MWERKS__` definition of `lbl_80419568` because no
   unit of ours claims that `.sbss` slot. Here `gLoader_MysteryFlyer` is claimed *and* defined
   by `MysteryFlyer.cpp`, so `extern void* gLoader_MysteryFlyer;` is the whole declaration and
   the port's undefined count provably cannot move (291 before and after). Prefer a candidate
   whose slot is already claimed: it is a four-file change with no host-block judgement in it.

3. **A carve setter next to its own thunk needs no edit anywhere else.**
   `CMysteryFlyerRel.cpp` was not touched: its `extern "C" void fn_80232868(FScriptLoader*)`
   already exists precisely because the name could not move. If you are carving a setter whose
   REL module has already been reimplemented, check that declaration first - if it is there,
   your change is exactly four files plus one stale comment.

4. **`stw r3,0(0)` in `carve_diff.sh` output is expected, not a failure.** It is the SDA21
   relocation before linking; the DOL sha1 is what proves the store landed at `-26432(r13)`.

5. **Not measured, do not assume: a count of how many same-shape 8-byte setters remain.** A
   scan of `build/G2ME01/asm/auto_*_text.s` for the `stw r3, <slot>@sda21(r0)` / `blr` pair and
   then comparing every `.fn` in the file against `splits.txt` gives hundreds of hits, but the
   result is **wrong**: in a multi-function auto unit the regex attributes the one store to
   every function in the file. The pair has to be matched per `.fn` block. The one candidate
   below was checked that way; the rest of the vein was not.
