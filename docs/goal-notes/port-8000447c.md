## What was wrong

The ninth upstream sync (2026-10-02) renamed 0x8000447C to `__dt__11CWorldStateFv` in
`config/G2ME01/symbols.txt:75`, so retail's link has no `fn_8000447C` any more.
`src/MetroidPrime/Carve80004438.c:71-80` handles that with an `#ifdef __MWERKS__` guard that
`#define`s the old name to the new one, so the matching build's `bl` at 0x80004468 is retail's own
relocation. **The host build keeps the old name** and nothing defined it: an earlier stand-in for
this symbol in `PortLinkStubs.cpp` (`stub_197`, added by goal item `carve-80004438`) was lost when a
rebase union-merged that lane's `stub_197` with another lane's `stub_197` of the same number
(`docs/goal-notes/carve-80004438.md:478`), and `stub_199` is `fn_801FDAE8`, so nothing covered it
afterwards. `Carve80004438.c`'s own comments named `stub_199` as the stand-in, in both directions.

main.dol (measured: `sha1sum build/G2ME01/main.dol` is `6ef9b491d0cc08bc81a124fdedb8bfaec34d0010`

## Corrected, not inherited: the collision with `carve-8000447C` does not exist

Goal item `carve-8000447C` (lane 2, also carrying a passing change) states in
`build/goal/notes/carve-8000447C.md:169-174` that this unit "defines `fn_8000447C`", so a stand-in
"would now be a duplicate definition", and tells the next lane to skip the stub. **That is wrong, and
it is worth recording because the next lane would have skipped a real gap.** Two independent
measurements:

- `wt-mp2-goal-L2/src/MetroidPrime/Carve8000447C.cpp:136-147` defines the destructor as
  `__dt__11CWorldStateFv` and says why: "retail's link has no `fn_8000447C` any more, which is why
  `Carve80004438.c:71-80` rewrites its own `bl` under `#ifdef __MWERKS__` and why the definition
  below has to *be* `__dt__11CWorldStateFv`". It defines `fn_80004510` as well, never `fn_8000447C`.
- **Measured on lane 2's own tree after its carve and its two stand-ins** (`build-port-link/`, mtime
  18:00): `link_summary.txt` reads `287 0 0 1` and `fn_8000447C` is still row 243 of
  `link_undefined.txt`. The carve closes no `fn_8000447C` for the host.

So the two changes are **complementary**: the carve claims 0x8000447C..0x800045A0 and defines the
DOL's `__dt__11CWorldStateFv`; this one closes the host-only `fn_8000447C`. They can both land -
287 -> 286 here, and 287 -> 286 there - with no duplicate definition. (The `281 -> 283 -> 281`
arithmetic in `carve-8000447C.md:961-964` already implied this: 283 is 281 plus its two new
callees with *nothing* closed, so `fn_8000447C` cannot have been closed.)

**The better end state, for whoever wants it** (not this item, and no `NEW:` line: it raises no
count): once `Carve8000447C` is in, drop the `#ifdef __MWERKS__` guard in `Carve80004438.c` so both
builds spell the same name, and retire this stand-in - `main.dol` is unaffected either way, because
the guard is only ever inactive on the host.
