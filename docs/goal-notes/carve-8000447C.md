## What this run measured that the earlier run did not

**1. `asm` labels are not a route to naming a member function, so the `fn_`-named callees must be
reached through a *destructor that calls a free function*.** `void ReleaseData() asm("fn_80009224");`
inside a class is rejected by mwcceppc 2.7:

```
#       1: struct Base { int a; int b; virtual void ReleaseData() asm("fn_80009224"); };
#   Error:  type cannot be made into a global register variable;
#   Error:  only scalers, doubles, floats and vectors are supported.
```

(an `asm` label on a *free* function declaration is fine — that is what `PortLinkStubs.cpp` uses.)
The working spelling is a local base struct whose destructor calls the `extern "C"` name, with the
member type derived from it one level:

```cpp
struct SLayerStateMemberBase { void* x0_ptr; int* x4_refCount; ~SLayerStateMemberBase() { fn_80009224(this); } };
struct SLayerStateMember : SLayerStateMemberBase {};
...
self->mLayerState.~SLayerStateMember();
```

Compiled and measured: that emits exactly `addic. r0,r30,28 / beq / addic. r0,r30,28 / beq /
addi r3,r30,28 / bl`. **A direct call loses the pair**: `fn_80009224(&self->mLayerState)` emits
`addi r3,r30,28 / bl` and only — 2 instructions where retail has 6, and the whole function comes out
24 bytes short. That is the concrete A/B behind the earlier run's "the pair is `ncrc_ptr`, not a
written guard", and it is the same trade `src/MetroidPrime/ScriptObjects/Carve80213320.cpp:132-136`
records. The pair of null tests is one null test per **class level**, and both routes to the pair
are derivations of the member type rather than a hand-written guard.

**2. The `CWorldState` member layout is exactly what `CGameState.cpp:1304-1316` documents, and one
extra word is a real 4-byte-per-instruction error.** `mRelayTracker` +0x08, `mMapWorldInfo` +0x10,
`mDesiredAreaAssetId` +0x18, `mLayerState` +0x1C — **no padding word at +0x14**. With a padding word

**3. `fn_80004510`'s item array is *inline at +0x04*, not a pointer field, and the loop's increment

| spelling | differing instructions |
| --- | --- |
| pointer field `rc_ptr<T>* mItems` (cursor setup becomes `lwz r30,4(r28)`) | 5 |
