## The one thing that cost time, and it is worth a `NEW:`-free lesson here

**I first wrote this as a `.c` file, as the seed's "plain C so the fn_ names do not mangle" rule
says, and it was 8 bytes short in `fn_80256F20`.**  Two problems, both real:

1. **Plain C cannot express the shape.**  `fn_80256FD8` takes its two iterators **by value as a
   one-pointer class** (`lwz r31,0x0(r3)` at 0x80256FE8 is `begin.current`; `mr r29,r4` +
   `lwz r0,0x0(r29)` at 0x80257014 is `end.current` re-read every iteration).  Written as `void**`
   in C, the same logic is 0x20-byte frame instead of 0x30, one `stw r0,0x8(r1)` instead of the
   four stores at 0x80256F74/0x80256F7C/0x80256F80/0x80256F84, and a `destroy` loop that keeps its
   cursor in memory (`lwz r3,8(r1) / addi r0,r3,32 / stw r0,8(r1)`) instead of in r4.  The fix is
   a C++ `struct SAreaSurfaceIter` with a **converting constructor**, passed by value - exactly
   what `Carve801FF5A0.cpp:119-122` documents ("built by a converting constructor so that
   `fn_801FF5A0`'s two temporaries come out as they do").  So the unit is a `.cpp` with
   `extern "C"`, which is what the seed's own rule is protecting: `symbols.txt` carries
   `fn_<addr>` and a C++ definition outside `extern "C"` would mangle to `_Z<len>fn_<addr>v`.
   **`Carve801EF84C.cpp` and `Carve801FF5A0.cpp` are both `.cpp` carves for exactly this reason**,
   so the extension is not the constraint the seed states it is - the *symbol* is.
2. **mwcceppc compiles this unit as C89**: `void* newData = allocate(...)` after an `if` block is
   `expression syntax error`.  Declarations go at the top of the function.
