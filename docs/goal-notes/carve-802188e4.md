## Why `.c` and not `.cpp` - measured, not assumed

The queue's reason repeats the old claim that this cannot be claimed: "REL modules import it by
its retail name, so it cannot be renamed". That is true and it is not a reason to leave it in an
`auto_*` unit - it is a reason to use a C file. The import is real:

```
$ strings build/G2ME01/DarkSamus/DarkSamus.plf | grep 802188E4
fn_802188E4
```

`.c` is compiled with `-lang=c` (`src/MetroidPrime/Carve800069AC.c:36-40`), so the definition
below *is* the symbol; a `.cpp` would let mwcceppc mangle `fn_802188E4` into a name the module
does not import. `Carve8021887C.c` - the same carve shape one address along, landed in
`carve-8021887c` - is the working precedent. Its header, and `CScriptDarkSamusBattleStageRel.cpp:46-60`
for the `fn_80235DCC` twin, both carry the same argument.

## The body

```c
struct SDarkSamus_FuncPtrs;
extern struct SDarkSamus_FuncPtrs* gLoader_DarkSamus;

void fn_802188E4(struct SDarkSamus_FuncPtrs* loader) {
  gLoader_DarkSamus = loader;
}
```

- **The store target is already owned by another unit.** `gLoader_DarkSamus` is
  `.sbss 0x804193D0..0x804193D8` (`config/G2ME01/symbols.txt:20707`, `type:object size:0x8
  data:4byte`), claimed and defined by `DarkSamus.cpp` (`splits.txt:1542-1544`, definition at
  `DarkSamus.cpp:16`). This unit therefore claims `.text` only and declares the slot `extern`,
  which is what keeps it defined in exactly one unit. `DarkSamus.cpp:11-14`'s `SLoaderSlot` is
  `{ FScriptLoader* value; unsigned int padding; }` and `LoadDarkSamus` calls member 0 of it, so
  the slot holds one pointer-sized value; the store's small-data displacement comes out identical.
- **The argument type is a source-only spelling.** MWCC does not encode a variable's type in its
  name, so the `extern` above resolves to `gLoader_DarkSamus` whatever the type is spelled. The
  name is taken from Prime 1's mangling of the same function in the other game:
  `SetSDarkSamus_FuncPtrs__FP19SDarkSamus_FuncPtrs` at `config/R3ME01/symbols.txt:1665`
  (0x800747FC). Echoes' module is one of the 526-of-535 whose retail names are `fn_<offset>`, so
  there is no better name for the function itself and it must keep `fn_802188E4`.
- **Both of the module's two call sites pass a plain pointer**
  (`build/G2ME01/DarkSamus/asm/auto_00_0000CED0_text.s`): `RELExit` at 0xCEE0 materialises
  `li r3, 0` first, and `fn_10_CF14` at 0xCF30 stores a member pointer at the first word of
  `lbl_10_bss_110` and hands its address over. Nothing here reads through the pointer, so the
  record is deliberately an incomplete type here.
- **Declared at file scope, not inside the parameter list.** A tag first seen in a prototype is
  scoped to that list, and the host build then rejects the definition as a conflicting type -
  the trap `Carve8021887C.c:59-62` records for the Sandworm twin, hit and fixed the same way.
