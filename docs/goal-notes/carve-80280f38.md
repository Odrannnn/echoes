## The correction that made it a one-try item

**The claim in `docs/goal-notes/carve-80281310.md` that "a carve unit that has to reach a
MWCC-mangled symbol cannot be written at all" is wrong, and this run is the disproof.** That lane
measured the right thing - `<`, `>` and `,` are not identifier characters and mwcceppc has no
`__asm__` symbol renaming, so no C *declaration* can name
`__dt__Q24rstl37vector<Pv,Q24rstl17rmemory_allocator>Fv` - and stopped there. It never tried the
route `src/MetroidPrime/Carve8000447C.cpp` and `src/MetroidPrime/Carve801C2D74.cpp` already use:
**do not declare the symbol, declare the class that owns it, with the destructor declared and never
defined, and let mwcceppc mangle the destructor call itself.** The symbol then appears in the object
as a relocation and nothing is emitted for it.

exact `cflags` from `build.ninja:7236-7251`):

Nine instructions, retail's nine words in retail's order, the `-1` flag **materialised by
mwcceppc** rather than written in the source, one defined text symbol and no local definition.
That is the whole reason the item was cheap. Two properties of the recipe that the earlier lane's
note did not have:

- the class must be **complete** (so `self->~vector()` is legal) but need not have the real layout -
  only the **name** matters, because a mangled symbol encodes the name and nothing else;
- `include/rstl/vector.hpp` must **not** be included. Its `~vector()` is declared at :60 and
  *defined inline* at :138-142, so a TU that can see the body would either inline the deallocation
  into the 9-word function or outline a local weak copy of retail's own 0x8005C42C, which this
  36-byte range does not define (`tools/unit_fit.sh` would say "extra function"). Declared bare,
  nothing is emitted. This is the same constraint `Carve801C2D74.cpp:62-65` records for
  `rstl::construct_impl` and `rstl::pointer_iterator`.

## What the function is

It is `rstl::destroy_impl< rstl::vector< void* > >`, i.e. `in->~T()` and nothing else -
`include/rstl/construct.hpp:84-90`. The seed's twin is exact and confirmed word for word:
`fn_80004458` (0x80004458, 0x24 = 36 B, 9 instructions, `src/MetroidPrime/Carve80004438.c:89`,
`Matching`), the same nine words with a different `bl`. The twin has to **spell** the `-1` because
it calls the destructor through a plain C function; here mwcceppc emits it, and the file says so.

The `-1` is MWCC's "destroy, do not free me" flag, and the callee reads it:
`__dt__Q24rstl37vector<Pv,Q24rstl17rmemory_allocator>Fv` (0x8005C42C, 0x54,
`symbols.txt:1813`) does `mr r31,r4` (0x8005C43C) ... `extsh. r0,r31 / ble` (0x8005C454/58), so a
flag of `-1` skips its own trailing `bl Free__7CMemoryFPCv`. That is what makes this `destroy_impl`
and not a `delete`. Its own body is `mr. r30,r3 / beq`, `lwz r3,0xc(r30) / bl Free__7CMemoryFPCv`
(the `mItems` release, member at +0xC per `include/rstl/vector.hpp:18-21`), then the flag test and
the self-free.

## Two things the seeder should know

Both are about `tools/goal_seed.py`'s plan, not about this item:

1. **A carve whose only `bl` target is a MWCC-mangled template symbol is writable.** It costs a
   `.cpp` instead of a `.c`, a locally declared class template with its destructor never defined, and
   `extern "C"` around the definition. See "The correction" above. Seeding may stop skipping those
   functions; what it should still skip is a function that *defines* a template instantiation
   locally, because that puts an extra function in the object (`Carve80281310.md`'s `fn_802813C4`
   case stands).
2. **A carve that calls into an existing unit's mangled symbol needs no port stand-in at all**,
   because the mangled name does not exist in the host ABI. The `#ifdef __MWERKS__` guard is
   enough; the port's undefined count stayed at its baseline of 287.
