## The two spellings that mattered (both measured, not guessed)

* **`do_erase`: assign the already-computed `result`.**  The list.hpp source line
  `mStart = node->get_next()` gives a **0x78**-byte function with a `lwz r3,4(r4) / mr r31,r3`
  (the CSE'd load lands in r3 and is moved to r31): 110 of 116 instructions differ.  Writing
  `self->mStart = result;` instead is byte-exact.  Same shape as anything else that returns the
  erased node.
* **`~list()`: keep the template's three variables.**  A two-variable loop
  (`node = mStart; while (node != mEnd) { next = node->mNext; Free(node); node = next; }`) keeps
  the cursor in r3 and needs an extra `mr` (14 differing instructions).  The form
  `cur = mStart; while (cur != mEnd) { it = cur; next = cur->mNext; cur = next; Free(it); }` -
  exactly `include/rstl/list.hpp:251` - is byte-exact.  The loop-cursor register is decided by how
  many variables the source names, not by what it computes.
