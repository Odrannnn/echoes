## The spelling, and why it is in that order

```c
void fn_8028B728(struct SCarve8028B728Vector* self, const void* in) {
  unsigned int count = self->x04_count;
  void* items = self->x0c_items;
  unsigned int offset = count * 0x50;
  self->x04_count = count + 1;
  fn_8028B760((char*)items + offset, in);

```

Retail's order is load-count, load-items, `mulli`, `addi +1`, store, `add`, `bl`. The `offset` local
is there to hold the multiply before the store; written as `self->x04_count = count + 1;` first and
`(char*)items + count * 0x50` second it is the same computation in a different statement order, and
statement order is what decides the register this instruction lands in. Worth keeping in mind that
this ordering was **not measured against a failing alternative** — it is the order the twin's C++
template produces, adopted on that reasoning and not re-measured. A future lane that has to touch
this body should try the single-store spelling first before re-deriving anything.
