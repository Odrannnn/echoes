## The one thing that cost time: an SDA reference to a `.data` symbol

The obvious spelling of the extern is `extern void* lbl_803B86B8;`. It builds, and
then mwldeppc refuses the link:

```
### mwldeppc.exe Linker Error:
#   Small data relocation (109) in function 'fn_8022A060'
#   in referencing file 'Carve8022A060.o'
#   requires that symbol 'lbl_803B86B8'
#   in symbol definition file 'auto_07_803B8578_data.o'
#   be in a small data section but is in .data;
```

mwcceppc treats a plain `extern` object as small data and emits an SDA-relative
reference; retail emits `R_PPC_ADDR16_HA/LO` (`lis r5,@ha` / `addi r0,@l`). The fix is
the tree's existing spelling for "this is not small data" - an extern of
**unknown-size array type**, `extern const char lbl_803B86B8[];` - which produces the
`HA/LO` pair and the exact retail bytes. Same spelling and same reason at
`src/MetroidPrime/CErrorOutputWindowCtor.cpp:105` (unclaimed vtable `.data
0x803B5910`) and `src/MetroidPrime/CMainFlowCtor.cpp:37`. **Anyone carving a store
through a symbol in retail's `.data`/`.rodata` should reach for `extern const char
sym[];` first**, not `extern void* sym;`.
